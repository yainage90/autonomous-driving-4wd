# T9.3 world–map 오프라인 정합 확인

2026-10-20, 현재 저장된 지도와 평가 월드 파일을 직접 비교했다.
Gazebo 주행을 새로 실행하지 않았으며 코드·설정·지도·실행 중 TF는 변경하지 않았다.

## 판정

저장 지도 해상도 0.05 m 수준에서 월드와 지도의 형상 관계를 확인했다.
벽·장애물의 점유 경계 셀 중심을 기준으로 한 간단한 변환은 다음과 같다.

```text
x_map = x_world + 2.036
y_map = y_world + 0.020
yaw_map = yaw_world
```

이 값은 물리적 표면의 위치를 mm 단위까지 보증하는 보정값이 아니다.
지도 한 셀 안에서 실제 표면이 어디에 있는지는 이 분석만으로 알 수 없다.
기존 RViz 3점 클릭에 의존했던 큰 정합 불확실성은 파일 기반 비교로 좁혔다.
현재 도착 위치 합격 기준은 0.10 m이며, 셀 중심 정합의 불확실성을 포함한
평가 결과와 최종 설정은 [1차 시뮬레이션 검증 결과](simulation_validation.md)를 따른다.

## 입력과 계산 방법

- 지도: `src/vehicle_localization/maps/evaluation.yaml`, `evaluation.pgm`.
- 월드: `src/vehicle_simulation/worlds/evaluation.sdf`.
- YAML의 origin과 resolution으로 각 이미지 셀의 map 좌표를 계산했다.
  이미지 행 방향을 반전하고 셀 중심에 반 셀을 더했다.
- 바닥을 제외한 월드 박스의 collision 면을 사용했다.
- 관측된 자유 셀과 직접 인접한 점유 셀 562개 면 표본을 추출했다.
  미관측 영역이나 이미지 바깥쪽을 자유 공간으로 취급하지 않았다.
- 기존 근사 변환 `(2, 0, 0)`으로 같은 방향의 면에 대응시켰다.
  끝점으로부터 0.10 m 이내 및 대응 조건을 충족하지 않는 64개 표본을 제외하고,
  12개 면의 498개 표본으로 비교했다. 전체 점유 셀을 검증한 결과는 아니다.
- 면마다 같은 총 가중치를 부여해 평행 이동·회전만 계산했다.
  축척 변경, 목표 위치, AMCL 출력은 정합에 사용하지 않았다.
- 외벽만으로 계산한 변환을 나머지 장애물에 적용하고,
  중앙 장애물과 막힌 구역에서도 각각 독립적으로 변환을 계산했다.
  검증은 서로 다른 형상 구역의 비교이며 별도의 지도 작성 실행에 대한 검증은 아니다.

| 계산에 사용한 구역 | tx [m] | ty [m] | yaw [deg] | 계산에 쓰지 않은 구역의 잔차 RMS / 최대 [m] |
|---|---:|---:|---:|---:|
| 외벽 383개 표본 | 2.03600 | 0.01948 | 0.26395 | 0.00534 / 0.01101 |
| 중앙 장애물 56개 표본 | 2.03600 | 0.02000 | 약 0 | 0.01407 / 0.05000 |
| 막힌 구역 외측 59개 표본 | 2.03600 | 0.02000 | 약 0 | 0.01412 / 0.05000 |
| 전체 498개 표본, 최소제곱 | 2.03680 | 0.01820 | 0.14462 | 해당 없음 |
| 전체 498개 표본, Huber 손실 | 2.03623 | 0.01945 | 0.04201 | 해당 없음 |

잔차는 관측된 점유 경계 셀 중심에서 대응한 변환 후 월드 면까지의 수직 거리다.
통계적 신뢰구간이나 실제 표면 위치 오차의 상한을 의미하지 않는다.

`(2.036, 0.020, 0)`을 적용하면 498개 중 463개 표본이 셀 중심 기준으로
월드 면과 사실상 일치한다. 나머지 35개는 북·남 외벽의 일부이며,
주된 벽 선보다 실내 방향으로 한 셀(0.05 m) 이동한 표본이다.
전체 RMS는 약 0.01326 m, 최대 잔차는 0.05 m다.

다음은 기존 세 점 클릭과 독립적으로 확인한 대표 표면 위치다.

| 같은 물리적 표면 | world 좌표 [m] | map의 주된 점유 경계 셀 중심 [m] |
|---|---:|---:|
| 서쪽 외벽 안쪽 x | -2.950 | -0.914 |
| 동쪽 외벽 안쪽 x | 2.950 | 4.986 |
| 남쪽 외벽 안쪽 y | -1.950 | -1.930 |
| 북쪽 외벽 안쪽 y | 1.950 | 1.970 |
| 중앙 장애물 서쪽 x | -0.300 | 1.736 |
| 중앙 장애물 동쪽 x | 0.300 | 2.336 |
| 중앙 장애물 남쪽 y | -0.600 | -0.580 |
| 중앙 장애물 북쪽 y | 0.600 | 0.620 |

주된 남·북 벽 선 간격은 world와 map 모두 3.90 m이며,
중앙 장애물도 두 좌표에서 폭 0.60 m, 높이 1.20 m다.
이전 클릭 측정의 약 3.8006 m를 지도 전체의 축척 오차 근거로 삼을 수 없다.
관측한 형상에서는 지도 전체를 다시 작성해야 할 큰 변형의 증거가 없다.
미관측인 막힌 구역 내부 등은 이 결론에 포함하지 않는다.

## 도착 정밀도 튜닝 전 s01 관측에 미친 영향

원본 bag이 현재 작업 디렉터리에 없으므로, T9.3 문서에 남은 반올림된
최종 world 자세 `(-1.190767, -0.011219, 0.154250)`를 재계산했다.
현재 지도·월드와 과거 실행 입력의 완전한 일치 여부는 원본 사본 없이
재확인하지 못했다. 아래 값은 새 주행 결과나 원본 bag 재분석 결과가 아니다.

| 적용한 변환 | 위치 오차 [m] | 방향 오차 [deg] |
|---|---:|---:|
| 기존 RViz 3점 근사 | 0.14634 | 9.33945 |
| 이번 전체 최소제곱 | 0.15398 | 8.98249 |
| 이번 전체 Huber | 0.15470 | 8.87988 |
| `(2.036, 0.020, 0)` | 0.15502 | 8.83787 |

당시 대표 추정값은 약 0.155 m로, 초기 제안 기준인 0.15 m를 조금 넘었다.
그 차이 약 0.005 m는 지도 해상도보다 작았다. 셀 중심 잔차가 작더라도
물리적 표면과 지도 좌표의 대응 정확도가 그만큼 보장되는 것은 아니다.
따라서 당시 0.14634 m를 근거로 실제 도착 정확도 통과를 확정하지 않았다.
이 관측은 튜닝 전 이력이며 현재 0.10 m 기준의 통과 근거로 사용하지 않는다.
이후 도착 정밀도 튜닝 후 새로 실행한 평가 9회와 진행 판정 변경 후 s03 추가 3회는
참고 위치 오차·TF 위치 오차가 모두 0.10 m 이내였다.
해당 결과는 [검증 요약](simulation_validation.md)에 별도로 기록했다.

정밀한 통과 판정이 필요하면 물리적 기준과 지도 좌표의 대응을 더 정확히
정의해야 한다. 예를 들어 SDF에서 좌표 관계가 명시된 별도 평가 지도를
생성해 Nav2 위치 추정·주행을 평가할 수 있다. 이 경우 기존 SLAM 지도에서의
결과와 구분한다. 실제 오차가 기준을 초과하는 것으로 확인되면 위치 추정과
도착 허용 오차 설정 등을 점검한 뒤 s01~s03을 다시 평가한다.

## 재현 자료

로컬 분석 자료는 Git에서 제외되는 다음 디렉터리에 보관했다.

```text
evaluation_runs/world_map_alignment_20261020/
├── check_alignment.py
├── results.json
└── overlay.png
```

분석 스크립트는 시스템 Python 3.12의 numpy, scipy, Pillow, matplotlib,
PyYAML을 사용했다. 프로젝트 가상환경에는 설치하지 않았다.
동일 입력으로 재실행하려면 다음 명령을 사용한다.

```bash
/usr/bin/python3 evaluation_runs/world_map_alignment_20261020/check_alignment.py
```

분석 입력 SHA-256:
