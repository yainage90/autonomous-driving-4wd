# T1.4 명령 선택과 실차 watchdog 요구사항

## 명령 경로

- 수동 입력: `/cmd_vel_manual`
- 자율 입력: `/cmd_vel_auto`
- 최종 출력: `/cmd_vel`
- 메시지 타입: `geometry_msgs/msg/Twist`
- 최종 출력 발행자는 `command_guard` 하나로 유지한다.
- 시작 모드는 `manual`이다.
- `/set_auto_mode` 서비스(`std_srvs/srv/SetBool`) 요청이 `true`이면
  `auto`, `false`이면 `manual`을 선택한다.
- 선택되지 않은 입력은 무시하고 명령 타임아웃을 갱신하지 않는다.
- 수동·자율 입력 노드는 `/cmd_vel`에 직접 발행하지 않는다.

```text
수동 조종 → /cmd_vel_manual ─┐
                            ├→ command_guard → /cmd_vel → 구동기
자율주행 → /cmd_vel_auto ────┘
```

## 모드 전환

- 전환 요청 시 기존 명령 수신 시각을 초기화하고 0 명령을 먼저 발행한다.
- 그다음 선택 모드를 변경하며, 해당 모드의 입력을 다시 받기 전까지
  타이머로 정지 명령을 반복 발행한다.
- 모드 선택은 비상정지를 해제하지 않는다.
- 같은 모드를 다시 선택해도 정지 명령을 발행한다.
- 서비스 성공은 모드 선택과 정지 명령 발행 완료를 의미한다.
- 현재 구현에는 실제 차량 정지 완료를 기다리는 interlock이 없다.
  새 모드의 입력이 계속 발행 중이면 전환 처리 후 바로 전달될 수 있다.
- `Twist`에는 발행 시각이 없어 전환 후 수신한 입력의 생성 시점은
  구분하지 못한다.

## 현재 command_guard 설정과 동작

- 명령 타임아웃: 0.5초
- 타임아웃 검사 주기: 0.05초
- 최대 선속도: 0.2 m/s
- 최대 각속도: 0.6 rad/s
- 명령 타임아웃 측정과 검사 타이머는 steady clock을 사용한다.
- 주행 중에는 수신한 명령을 처리해 출력하며 별도 주행 heartbeat는 없다.
- 명령이 없거나 비상정지 상태이면 타이머로 0 명령을 반복 발행한다.
- `command_guard`가 종료되면 이 노드의 타임아웃 처리와 정지 명령
  발행도 중단된다. 실차 구동기는 독립적인 watchdog이 필요하다.

## 실차 모터 제어기 watchdog 요구사항

다음 수치는 초기 제안값이며 하드웨어와 통신 지연 측정 후 확정한다.
현재 ROS 설정에 적용된 값은 아니다.

| 항목 | 초기 제안 |
|---|---|
| 정상 주행 명령 송신 주기 | 10 Hz 이상 |
| 모터 제어기 watchdog 타임아웃 | 0.3초 |

주행 출력이 입력 주기를 따르는 현재 구조에서는 입력 송신 주기도
함께 보장해야 한다. 정상 명령의 최대 수신 간격과 통신 지연을 측정해
watchdog 타임아웃을 확정한다.

- watchdog은 ROS 노드나 PC의 정상 동작에 의존하지 않고 모터 제어기에서
  직접 수행한다.
- 마지막 유효 명령 이후 타임아웃이 지나면 모터 정지 처리를 시작한다.
- 시간 측정은 제어기 내부의 단조 증가 시계를 사용한다.
- 잘못된 명령은 watchdog을 갱신하지 않고 정지 처리한다.
  유효성 검사는 메시지 형식, 유한한 속도 값 및 허용 범위를 포함한다.
- 제어기 시작 시 모터 출력은 정지 상태로 유지한다.
- watchdog 정지 후에는 통신 복구만으로 자동 재출발하지 않는다.
- 명시적 재활성화와 그 이후의 새 유효 명령이 있어야 주행을 허용한다.
  재활성화 절차와 인터페이스는 실차 구동기 구현 시 정의한다.
- 제어기 비상정지는 명령 수신이나 모드 선택으로 해제되지 않는다.
- 정지 시 브레이크 또는 출력 차단 방식은 모터 제어기 사양에 맞게
  확정한다.

## 실차 검증 항목

하드웨어 구현 단계(H2)에서 다음 시험을 수행한다.

- 정상 주행 중 `command_guard` 프로세스 종료
- 정상 주행 중 PC와 모터 제어기 사이 통신 단절
- 비정상 명령 수신
- 통신 복구 후 자동 재출발하지 않는지 확인
- 명시적 재활성화 이후 새 명령으로 주행하는지 확인
- 정상 송신 주기와 예상 통신 지연에서 불필요한 watchdog 정지가
  발생하지 않는지 확인

각 시험에서 마지막 유효 명령 수신부터 정지 처리 시작까지의 시간과
실제 차량 정지까지의 시간을 별도로 측정한다.

## 현재 검증 결과

다음 결과는 사용자가 실행하고 확인한 결과이다.

- `vehicle_control` 단위·통합 테스트: 48개 통과
- 수동·자율 명령 동시 발행 시 선택된 모드의 명령만 출력
- 양방향 모드 전환 후 이전 입력이 계속 들어와도 정지 출력 유지
- 선택된 모드의 새 입력을 받으면 해당 명령 전달
- 전체 실행에서 `/cmd_vel` 발행자 하나(`command_guard`) 확인
- Gazebo에서 수동 → 자율 전환 시 0 출력 유지 및 차량 정지 확인
- Gazebo에서 자율 → 수동 전환 시 0 출력 유지 및 차량 정지 확인

실차 watchdog은 요구사항 정의 단계이며 구현과 실차 검증은 후속 작업이다.
