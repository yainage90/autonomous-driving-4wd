# 1차 시뮬레이션 검증 결과

실행 환경 분리 이후의 명령과 추가 회귀 결과는
[시뮬레이션·하드웨어 실행 분리](simulation_hardware_separation.md)에 기록한다.

2026-10-20, 이슈 #3의 위치 오차 합격 기준을 **0.10 m(10 cm) 이내**로 확정했다.
T1~T9.4의 구현·검증 결과를 바탕으로 1차 시뮬레이션 범위를 완료로 정리하고,
다음 단계는 실차 전환 H1~H6으로 진행한다.

이 문서는 사용자가 실행한 시험의 bag·JUnit 분석과 사용자 관찰을 정리한 것이다.
문서 갱신을 위해 새 주행이나 패키지 테스트를 실행하지는 않았다.

## 합격 기준과 제어 설정

| 평가 항목 | 합격 기준 |
|---|---|
| 정상 목표 도착 | s01 직선·s02 회전·s03 우회 각각 독립적인 3회 실행에서 성공 |
| 도착 위치 오차 | 목표에서 **0.10 m 이내** |
| 도착 방향 오차 | 목표 방향에서 10° 이내 |
| 최종 정지 | 평면 선속도 0.02 m/s 이하, 각속도 절댓값 0.05 rad/s 이하를 1초 유지 |
| 접촉 | 장애물·외벽을 포함한 접촉 0회 |
| 정상 목표 실행 시간 | 목표 제출 서비스 응답부터 최종 상태·정지 확인까지 실시간 120초 이내 |

위치 0.05 m·방향 0.05236 rad(약 3°)는 컨트롤러 튜닝값이며,
평가 합격 기준인 위치 0.10 m·방향 10°와 구분한다.
자동 통합 테스트의 **시작 위치** 허용 오차 0.15 m도 도착 위치 기준과 구분한다.

현재 설정은 다음과 같다.

| 파일 | 파라미터 | 값 |
|---|---|---|
| `vehicle_control/config/controller.yaml` | `goal_checker.xy_goal_tolerance` | `0.05` m |
| 같은 파일 | `goal_checker.yaw_goal_tolerance` | `0.05236` rad |
| 같은 파일 | `goal_checker.stateful` | `true` |
| 같은 파일 | `follow_path.xy_goal_tolerance` | `0.05` m |
| 같은 파일 | `progress_checker.plugin` | `nav2_controller::PoseProgressChecker` |
| 같은 파일 | `progress_checker.required_movement_radius` | `0.03` m |
| 같은 파일 | `progress_checker.required_movement_angle` | `0.10` rad |
| 같은 파일 | `progress_checker.movement_time_allowance` | `10.0` s |
| `vehicle_localization/config/amcl.yaml` | `update_min_d` | `0.05` m |
| 같은 파일 | `update_min_a` | `0.05` rad |

## 도착 평가 9회

`evaluation_runs/precision_s01_r1`~`precision_s03_r3`을 사용했다.
이 9회는 위치·방향 허용 오차와 AMCL 갱신 조건을 조정한 뒤,
진행 판정을 변경하기 전에 얻은 결과다. 진행 판정은 `SimpleProgressChecker`,
이동 `0.10` m, 허용 시간 `10.0` s였다.

9회 모두 위치 10 cm 이내, 액션 성공, 실제 정지 및 최종 명령 해제를 확인했다.
최대 참고 위치 오차는 8.71 cm, 최대 TF 위치 오차는 8.92 cm였다.
사용자는 이 9회 모두 장애물·외벽을 포함한 어떤 접촉도 없었다고 육안 확인했다.

## 마무리 지연 개선 후 s03 3회

이전 s03 2회차는 목표 근처에서 `Failed to make progress`가 두 번 발생했고,
복구 후 최종 성공까지 61.15초가 걸렸다. 해당 구간에도 회전·미세 이동을 하고 있었다.
회전을 진행으로 인정하도록 `PoseProgressChecker`로 변경하고 이동 기준도 0.03 m로 줄였다.
방향 도착 허용 오차는 약 3°로 유지했다.

`evaluation_runs/progress_s03_r1`~`progress_s03_r3`의 결과다.

| 회 | 참고 위치 오차 [cm] | TF 위치 오차 [cm] | 참고 방향 오차 [deg] | 제출→최종 상태 [s] | 최대 recoveries |
|---|---:|---:|---:|---:|---:|
| 1 | 2.52 | 6.75 | 1.85 | 32.96 | 0 |
| 2 | 3.53 | 6.57 | 1.40 | 32.07 | 0 |
| 3 | 6.43 | 7.04 | 0.66 | 33.96 | 0 |

3회 모두 위치 10 cm 이내, 액션 성공·실제 정지·최종 명령 해제를 확인했다.
`Failed to make progress`, 명령 타임아웃 정지 및 복구 재시도는 없었다.
완료 시간은 32.07~33.96초였고, 이번 반복에서 이전 중단·복구 지연은 재발하지 않았다.
실행 조건을 통제한 대규모 통계적 검증이나 모든 조건에서의 재발 방지 보증은 아니다.

## 근거와 확인 범위

- 총 12회 JUnit은 각각 1 test, 오류·실패·skip 0개다.
- 모든 실행에서 액션 `succeeded`, `error_code=0`과
  `sending → running → stopping → succeeded` 순서를 확인했다.
- 모든 실행의 최종 상태 이후 실제 속도 표본 60개에서 1.18초 연속 정지를 확인했다.
  표본 간격은 0.02초이며 평면 선속도·각속도는 모두 0이었다.
- 같은 종료 후 1.2초 구간의 최종 `/cmd_vel` 37~38개는 모든 축이 0이었다.
- 입력 사본의 해시를 manifest와 대조했다. 초기 9회끼리, 추가 3회끼리 설정이 동일했다.
  두 그룹의 차이는 controller의 진행 판정 설정이며 AMCL·지도·월드는 같았다.
- 초기 9회 무접촉은 사용자 육안 확인이다. 자동 접촉 검출은 없다.
  추가 3회의 무접촉을 초기 9회 확인으로 대신 판정하지 않는다.
- 도착 오차에는 [셀 중심 기반 좌표 정합](t9_3_world_map_alignment.md)의 불확실성이 포함된다.
  mm 단위 물리적 정확도나 정합 오차 상한을 보증하는 수치로 취급하지 않는다.
- 최종 진행 판정으로 추가 실행한 시나리오는 s03이다.
  s01·s02까지 모두 최종 설정으로 다시 3회씩 실행했다는 의미는 아니다.
- s04~s08은 [T9.2의 이전 평가](t9_2_evaluation_scenarios.md)의 근거와 범위를 유지한다.
  이번 정밀 도착 비교 시험에서 새로 반복한 결과로 계산하지 않는다.

## 기록과 재현

[T9.3](t9_3_observation_recording.md)에 따라 `record_run`으로 입력 사본과 bag을 보관하고,
생성된 `start_system.sh`로 회차마다 시스템을 새로 시작했다.
[T9.4](t9_4_regression.md)의 주행 통합 테스트로 목표 제출·결과·정지를 확인했다.
기록 종료 후 `metadata.yaml`과 `ros2 bag info`를 확인한 완성 bag을 분석했다.

```bash
source env.sh
ros2 run vehicle_simulation evaluate_run \
  --run-dir evaluation_runs/progress_s03_r1 \
  --map-from-world 2.036 0.020 0.0 \
  --alignment-note "지도-SDF 셀 중심 정합. 위치 합격 기준 0.10m, 지도 해상도 0.05m."
```

`evaluate_run`의 `ground_truth_stop_check`·`collision_check`는 `not_evaluated`로 남는다.
실제 정지와 잔여 명령은 통합 테스트 및 별도 bag 검토에서 확인했고,
접촉 여부는 위에 명시한 사용자 관찰과 구분해 기록했다.

원본과 로컬 상세 분석은 Git에서 제외되는 `evaluation_runs/`에 보관한다.

- `precision_navigation_review/`: 초기 9회 분석 및 사용자 무접촉 확인.
- `progress_s03_review/`: 진행 판정 변경 후 3회 비교 분석.
- `world_map_alignment_20261020/`: 좌표 정합 분석.

각 실행의 `analysis.json`, 상세 분석의 `results.json`·스크립트·보고서 및 원본 bag을
함께 보관한다. 이 문서는 로컬 원본을 보지 않아도 평가 기준·최종 수치·설정 차이와
확인 범위를 알 수 있도록 저장소에 남긴 요약이다.
